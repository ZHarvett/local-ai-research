## Why it cannot proceed

- Acceptance criterion 5 is the R3 command verbatim; `wf.sh accept T-001` fails on it. R3 is a
  planning-chat rule declared 2026-11-12; the card and PLAN.md are never hand-edited; code is
  frozen until T-008 is accepted (and `scripts/wf.sh` is a kit file besides). The session may not
  widen the regex, rename or remove `wf.sh`, or pass the criterion by other means.
- Card T-001 `must_escalate`: "any FAIL". Shared rule 7: escalate instead of working around an
  assumption mismatch. R3's stated intent ("the only changes ... are the kit's new scripts/wf-*.sh
  and scripts/_wf.py") did not account for the dispatcher's name `wf.sh`.

## Options

- **A. Amend R3's regex and acceptance criterion 5 to also match `scripts/wf.sh`**, e.g.
  `'CLAUDE\.md|\.gitignore|scripts/wf(-[A-Za-z0-9_.-]+)?\.sh|scripts/_wf\.py'` (equivalently, add
  `|scripts/wf\.sh`). The planning chat records the amendment through its own process (card/PLAN
  update); T-001 then re-runs accept. Consequence: the check keeps its intent (only kit scripts +
  CLAUDE.md/.gitignore since Stage 3). Cost: a one-line regex amendment; no code change, no
  re-measurement.
- **B. Keep the regex and move R3's anchor to a commit before the kit install.** Consequence:
  contradicts E-001/D6 (the anchor is the Stage 3 session commit 8096461; the kit install f149338
  is after it) and weakens the drift check. Not viable.
- **C. Rename or remove `scripts/wf.sh` to fit the pattern.** Consequence: breaks every `wf.sh`
  subcommand (the kit dispatcher), violates the code freeze and the kit manifest. Not viable.

## Recommendation

Option A — `scripts/wf.sh` has the same provenance as the seven `wf-*.sh` (one install commit
f149338, manifest-listed); allowing it restores the check's intent with no other change.
Confidence: high.
